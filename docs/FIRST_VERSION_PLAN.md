# AirControl 第一版项目规划

> 状态：B 方案设为默认主方案；A 方案保留为回退和对照。用户反馈 B 的识别和点击定位效果理想，默认入口和受安全控制的真实鼠标路径已实现，等待连续桌面操作与量化验收。
> 更新日期：2026-11-25
> 本文档用于确定第一版范围和验收依据，各项功能以对应阶段的验证结果为准。

## 1. 项目目标

使用普通摄像头捕捉单只手，通过手部位置和手势完成光标移动、左键点击、左键拖拽和页面滚动，形成一个基于 OpenCV 的空中鼠标原型。

第一版目标是完成上述基本操作并验证交互是否稳定。完整替代传统鼠标、长时间使用的舒适性以及复杂桌面场景的适用性，需要在后续使用测试中评估。

## 2. 第一版功能范围

| 功能 | 手势或触发条件 | 预期行为 |
|---|---|---|
| 光标移动 | 拇指与食指捏合并保持 | 从手势起点相对映射，光标跟随拇指尖 |
| 左键点击 | 瞄准后张开拇指与食指，其余手指收起 | 在候选离开捏合时冻结光标，确认后在冻结位置点击一次 |
| 左键拖拽 | 五指张开 | 按拇指尖相对位移移动，保持左键按下；退出张掌后释放 |
| 页面滚动 | 食指与中指伸直，其余手指收起，并上下移动 | 向上移动向上滚动，向下移动向下滚动 |
| 手部丢失处理 | 手离开画面或无法识别 | 停止输入，释放可能按下的左键，清除手势状态 |
| 预览模式 | 启动后的默认模式 | 显示画面、关键点和识别状态，不操作系统鼠标 |
| 控制模式 | 用户主动开启 | 将有效手势转换为真实鼠标操作 |

范围限定为单只手、普通摄像头、主屏幕操作。以 Windows 桌面作为首个验证环境；跨平台和多显示器适配留待后续确定。

## 3. 手势交互规则

### 3.1 移动光标

- B 方案以拇指和食指捏合启动相对瞄准，控制点跟随拇指尖。
- 相对移动从开始捏合时的屏幕位置起算，避免捏合启动导致屏幕坐标瞬移。
- 对坐标进行平滑，减少手部轻微抖动造成的光标晃动。
- 使用相对灵敏度缩放位移，减少到达屏幕边缘所需的手部移动范围。
- 不符合有效手势时保持光标位置；恢复识别时避免突然跳动。

### 3.2 点击与拖拽

- 使用拇指尖与食指尖的距离判断捏合，距离按手掌尺寸归一化，并使用进入/退出迟滞。
- 捏合瞄准后张开两指，候选离开捏合时冻结光标；确认点击时按下/释放左键，不追随张开时移动的拇指。
- 全掌张开进入拖拽，拇指尖相对移动虚拟光标；退出姿势后释放左键。
- 拖拽与点击状态互斥，拖拽结束不补发点击；丢手、暂停、超时和退出均释放左键。

### 3.3 页面滚动

- 进入滚动手势时记录手部的初始位置，切换时不立即产生滚动。
- 食指与中指伸直且其余手指收起时进入滚动，根据两指中点的纵向位移计算滚动量。
- 设置移动死区、滚动速度上限和输出频率限制；手保持静止时不持续滚动。
- 滚动期间冻结光标位置，结束后平稳恢复移动控制。

### 3.4 状态切换与退出

- 同一时刻只允许一种主要交互状态，避免边拖拽边滚动。
- 有效捏合优先于普通移动和滚动；拖拽期间不直接切入滚动状态。
- 手部丢失、关闭控制模式、主动退出或发生异常时，都应释放左键并清除状态。
- 提供暂停控制和退出的键盘快捷键，具体按键在开发时确定。
- 从预览模式进入控制模式后，先确认手势已回到松开状态，再接受新操作。

## 4. 第一版暂不包含

- 右键操作、专用双击手势。
- 双手协同、多手切换。
- 语音、音量、媒体和人脸控制。
- 移动端支持、多显示器适配。
- 自定义手势训练、复杂设置界面。

## 5. 技术方案

| 组成 | 建议技术 | 职责 |
|---|---|---|
| 摄像头与画面处理 | Python + OpenCV | 采集画面、镜像显示、绘制提示 |
| 手部追踪 | MediaPipe Tasks `HandLandmarker` | 使用模型输出单手的 21 个关键点及识别信息 |
| 手势判断 | 关键点几何关系 + 状态机 | 判断伸指、捏合和状态切换 |
| 光标处理 | 坐标映射 + 平滑处理 | 控制范围、抖动和移动连续性 |
| 系统鼠标控制 | PyAutoGUI，必要时评估 Windows 原生接口 | 移动、按下、释放和滚轮输出 |

以上为拟采用方案。Python、MediaPipe 和其他依赖的具体版本及接口，在开发前做兼容性验证后固定。

### 5.1 开发环境

第一版开发和验证使用 Windows，Conda 环境固定为：

```text
E:\conda_envs\AirControl
```

开发前应确认该环境可以正常激活，并在此环境中安装和冻结项目依赖。后续命令示例统一以该环境为前提；不在系统 Python 或其他 Conda 环境中混用依赖。

环境约定：

- 使用 Python 运行摄像头、手部追踪和手势逻辑。
- OpenCV、MediaPipe、PyAutoGUI 等依赖安装在 `E:\conda_envs\AirControl`，具体步骤见 [ENVIRONMENT_SETUP.md](ENVIRONMENT_SETUP.md)。
- 初期不要求额外的 GPU、模型训练或数据库。
- 当前已验证 Python 3.11.17、OpenCV 5.0.0、MediaPipe 1.1.1 和 PyAutoGUI 0.9.54；版本快照记录在 `requirements-lock.txt`。
- 摄像头和系统鼠标权限属于运行环境条件，应在阶段 1 和阶段 7 分别验证。
- 当前 MediaPipe 1.1.1 使用 Tasks API；Hand Landmarker `.task` 模型已保存至 `models/hand_landmarker.task`，来源和校验见 `models/README.md`。

处理流程：

```text
摄像头采集
  → 手部关键点检测
  → 坐标与手掌尺度归一化
  → 手势判断与状态管理
  → 光标平滑 / 滚动位移计算
  → 预览展示或系统鼠标事件
```

建议按摄像头采集、手部追踪、手势状态、鼠标控制和状态展示划分模块，使识别规则与系统操作可以分别调试。

## 6. 画面与调试信息

- 显示摄像头画面、手部关键点和有效操作区域。
- 显示当前模式：预览、控制或暂停。
- 显示当前状态：未检测到手、空闲、移动、捏合、拖拽或滚动。
- 显示帧率和必要提示，方便观察卡顿和识别切换。

## 7. 技术实现阶段

各阶段按顺序推进，每一阶段先完成可观察的结果，再进入下一阶段。除阶段 7 的受控验证外，前面的阶段默认不操作真实系统鼠标。

### 阶段 0：确认开发环境

工作内容：

- 激活 `E:\conda_envs\AirControl` Conda 环境。
- 确认 Python 版本、摄像头可用性和 Windows 屏幕信息。
- 安装并记录 OpenCV、MediaPipe、PyAutoGUI 的实际版本。
- 确认项目可以从该环境启动，避免依赖落入系统 Python。

阶段产出：环境检查记录和可复现的依赖清单。

### 阶段 1：摄像头与画面采集

工作内容：

- 打开指定摄像头并读取连续帧。
- 设置分辨率，镜像显示画面，并显示基础帧率。
- 处理摄像头无法打开、读取中断和正常退出。

阶段产出：只显示摄像头画面的最小预览程序，不识别手部，也不控制鼠标。

完成标准：画面可以稳定显示，按退出键后摄像头和窗口正常释放。

### 阶段 2：手部关键点识别（基础效果已确认）

工作内容：

- 使用 MediaPipe Tasks 的 `HandLandmarker` 检测单只手的 21 个关键点，不使用旧版 `mp.solutions.hands` 接口。
- 在画面上绘制关键点和骨架，显示手部是否被识别。
- 保存食指尖、拇指尖、中指尖及相关关节点的归一化坐标。
- 观察光线、手部远近和短暂遮挡对识别的影响。
- 在正式进入本阶段前准备 `.task` 模型文件，并记录模型版本、路径和来源。

阶段产出：`aircontrol/stage2_hand_preview.py` 预览程序、MediaPipe Hand Landmarker 模型及模型来源/校验记录。用户截图已确认单手 21 个关键点和骨架正常显示，约 19.7 FPS，具备进入阶段三的基础；复杂条件下的跟踪稳定性继续在后续阶段观察。

### 阶段 3：手势判断与状态机（已验证）

工作内容：

- 先实现 `NONE`、`MOVE`、`PINCH`、`SCROLL` 四种基础状态。
- 以关键点距离和手指弯曲关系判断捏合、伸指和滚动准备姿态。
- 对捏合距离做手掌尺度归一化。
- 使用捏合进入/退出双阈值、连续帧稳定判断和状态互斥，减少抖动和误切换。
- 只输出抽象状态和事件，不调用系统鼠标。

阶段产出：画面中可显示当前手势、状态变化和必要的调试数值。

当前实现：

- `aircontrol/gesture_detector.py` 输出稳定状态、候选状态、连续帧数、捏合比例、伸指判断和 `*_START` / `*_END` 事件。
- `aircontrol/stage3_gesture_preview.py` 复用阶段二摄像头和模型流程，仅显示状态和记录事件，不调用系统鼠标。
- 默认捏合比例进入/退出阈值为 `0.34 / 0.42`，手势确认帧数为 `3`，食指角度门槛为 `155°`；中指使用 `160°/150°` 伸直/弯曲迟滞门槛并需连续 `2` 帧确认，配置位于 `aircontrol/config.py`。
- 手部丢失或无效关键点立即复位到 `NONE` 并清空中指判断记忆；`DRAG` 仅预留，不在本阶段输出。
- 中指先经两帧确认，再经整体手势三帧确认（通常共四帧，约 30 FPS 时为 0.1 秒），减少 MOVE/SCROLL 误切换。模型仍输出整手 21 点；此次修改不直接修复食指关键点因遮挡而产生的跳动。新规则已通过合成关键点回归，实际手感待复测。
- `tests/test_gesture_detector.py` 使用合成关键点覆盖防抖、中指角度迟滞和连续帧确认、捏合优先级、事件顺序、尺度/宽高比处理和丢手复位。
- 验证结果：语法检查和手势检测回归测试通过；真实摄像头启动测试观察到状态事件，用户实际运行 `aircontrol/stage3_gesture_preview.py` 后确认手势效果符合预期。模拟 `Q` 退出可以正常返回，但含初始化和清理约 49.2 秒，退出等待问题仍需排查。

运行与实测步骤见 `README.md` 的阶段三部分。依据用户对整体预览效果的确认，阶段三标记为已验证；本次反馈未提供逐项测试记录。后续参数调整仍可根据不同光照、角度和手部远近继续记录。

### 阶段 4：光标坐标映射与平滑（基础实际预览已验证）

工作内容：

- 将食指尖的摄像头坐标映射到主屏幕坐标。
- 设置有效操作区域和边缘留白。
- 使用指数移动平均或同等方法降低光标抖动。
- 过滤手部丢失后的异常跳跃，并处理重新识别时的起始位置。
- 在预览画面中显示“预计光标位置”，暂时不移动真实光标。

阶段产出：可观察、可调参数的光标位置映射模块。

当前实现：

- `aircontrol/cursor_mapper.py` 独立处理操作区域映射、边界夹紧、按时间修正的指数平滑与速度限制，不依赖系统鼠标库。
- `aircontrol/stage4_cursor_preview.py` 读取 Windows 主屏幕尺寸，复用摄像头与手势流程，显示原始目标及平滑后的预计光标。
- 默认横纵边距各 `0.15`，平滑系数 `0.25`（以 30 FPS 为基准），另有 `4` 屏幕像素低速抖动死区；最大速度为每秒 `1.5` 个屏幕对角线，单帧时间最多取 `0.05` 秒。
- 已确认状态和候选状态均为 `MOVE` 时更新，其他状态立即暂停并清空位置和滤波历史；暂停画面不绘制旧光标或旧坐标。
- 重新确认 `MOVE` 后从当前食指位置初始化，再按常规参数平滑跟随。
- `tests/test_cursor_mapper.py` 含 12 项映射/滤波测试，`tests/test_stage4_cursor_preview.py` 含 5 项预览集成测试，覆盖 4 像素死区内抖动抑制和微动累积；与阶段三合计 28 项通过。当前参数调整后的真实手感待用户复测。
- 用户提供的实际预览截图确认 `MOVE`、20.1 FPS、屏幕 `2560×1600`，目标 `(1493, 721)` 与平滑后位置 `(1499, 717)` 正常显示。

基础映射和实时预览已验证。2026-11-10 将默认平滑系数从 `0.35` 调至 `0.25`，并加入 `4` 屏幕像素低速抖动死区；自动测试验证死区内静止、连续微动累积、重置和纯平滑滤波。新参数的实际延迟、阶梯感和小按钮瞄准改善程度待用户摄像头实测。四角边界及暂停恢复仍可继续观察。退出等待问题继续保留为已知限制。

### 阶段 5：左键点击与拖拽

工作内容：

- 将捏合开始、持续捏合和松开分别建模。
- 快速捏合并松开时输出一次左键点击。
- 捏合期间移动超过拖拽阈值后进入拖拽状态，松开时释放左键。
- 增加点击冷却、移动阈值和统一的 `release_all` 清理路径。
- 先使用可记录的模拟事件验证状态转换，再接入真实鼠标按键。

阶段产出：点击和拖拽事件序列正确，且不会重复点击或残留按键。

当前实现：

- `aircontrol/click_drag_controller.py` 只维护模拟按下、捏合、拖拽和统一释放状态，不依赖鼠标控制库。
- `aircontrol/stage5_click_drag_preview.py` 将稳定手势、阶段四光标映射和动作状态机连接起来；短捏合产生一次 `CLICK` 记录，持续移动超过阈值进入 `DRAGGING`，松开后只结束拖拽。
- 点击位置固定在捏合前的预计光标锚点；拖拽位移从捏合确认时的手指位置累计，减少捏合动作本身造成的光标偏移。
- 启动后需先确认稳定 `MOVE` 才启用动作；松开候选期间冻结动作坐标，等待状态确认后再结束动作。
- 默认点击冷却为 `0.35` 秒，点击最长时长 `0.8` 秒，拖拽起始位移 `48` 像素，拖拽事件最小移动量 `1` 像素；配置位于 `aircontrol/config.py`。实际观测复现了短捏合进入拖拽，结合代码判断，24 像素阈值可能容易被捏合位移或抖动越过；48 像素为首轮调参值，尚未验证误判率改善。
- 手部丢失、无效关键点、状态切换、相机循环退出和异常退出均调用统一清理路径，清除模拟按下状态。
- `tests/test_click_drag_controller.py` 与 `tests/test_stage5_click_drag_preview.py` 的 18 项测试覆盖点击、冷却、拖拽、手部丢失、无效坐标、启动防误触、松开抖动和正常/异常清理流程；加入中指稳定性测试后，完整回归共 47 项通过。2026-10-23 对实际手势进行了约一分钟的窗口抽样观察和事件日志检查：帧率约 29，既出现正确点击，也复现短暂拖拽及 `GESTURE_NONE` 取消；日志没有每帧位移和时间，无法据此计算点击准确率。新阈值已启动确认显示，仍需手感对比复测。

运行方式、事件说明和手动验证步骤见 `README.md` 的“阶段五预览：左键点击与拖拽”。此阶段没有真实系统鼠标输入。

### 阶段 6：页面滚动

工作内容：

- 使用食指和中指同时伸直进入滚动状态。
- 记录进入滚动时的基准位置，按连续帧纵向位移计算滚轮增量。
- 加入滚动死区、速度上限和输出频率限制。
- 滚动期间冻结光标移动，禁止与捏合拖拽同时生效。

阶段产出：先验证模拟滚动事件方向和静止抑制；阶段七接入真实滚轮后，再验证长页面滚动。

当前实现（2026-10-24）：

- `aircontrol/scroll_controller.py` 维护 `IDLE/SCROLLING`，输出 `SCROLL_START`、`SCROLL_UP`、`SCROLL_DOWN` 和 `SCROLL_END`。
- `aircontrol/stage6_scroll_preview.py` 复用阶段五会话，保留移动、点击和拖拽模拟。双指伸直且确认/候选均为 `SCROLL` 时才滚动，进入时仅建立基准；滚动中冻结预计光标，候选离开滚动立即停止。
- 输入为两指指尖中点的摄像头纵坐标，向上对应 `SCROLL_UP`，向下对应 `SCROLL_DOWN`，不使用屏幕映射坐标放大位移。

先在固定摄像头、光线充足、单人单手和主屏幕环境中验证。每项记录测试条件、尝试次数、成功次数及异常现象；具体准确率和延迟目标待初次原型测试后确定。

- [ ] 预览模式可观察识别结果，真实鼠标位置和按键状态不受影响。
- [ ] 开启控制后，捏合移动拇指尖可到达屏幕中心及四角附近。
- [ ] 手保持稳定时，光标抖动不会明显妨碍选中目标。
- [ ] 瞄准后张开拇指与食指只产生一次原位点击，不连续重复触发。

- [ ] 拖拽结束不会额外产生一次点击。
- [ ] 两指上下移动可以按约定方向滚动页面，静止时停止滚动。
- [ ] 滚动期间不会同时移动光标或触发左键。
- [ ] 手部离开画面后停止输入，左键不会残留按下状态。
- [ ] 暂停、退出和异常清理均能释放鼠标。
- [ ] 从预览或暂停恢复控制时，不因已有捏合状态立即误触。

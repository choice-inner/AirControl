# AirControl 开发阶段记录

本文保留各阶段实现与测试记录；日常使用见 [使用说明](USER_GUIDE.md)，项目结构与当前入口见 [项目首页](../README.md)。以下命令从项目根目录执行。

## 阶段三预览

```powershell
& E:\conda_envs\AirControl\python.exe -m aircontrol.stage3_gesture_preview
```

同样支持 `--camera 1` 和 `--model <路径>`；按 `Q` 或 `Esc` 退出。画面显示当前确认状态、候选状态、连续帧数、捏合比例和最近的状态变化事件，控制台也会输出事件。

| 手势 | 状态 | 观察内容 |
|---|---|---|
| 食指伸直、中指收起，拇指离开食指 | `MOVE` | 稳定后输出一次 `MOVE_START` |
| 拇指与食指捏合 | `PINCH` | 优先于移动与滚动，输出 `PINCH_START` |
| 食指与中指同时伸直，未捏合 | `SCROLL` | 稳定后输出一次 `SCROLL_START` |
| 收起食指，拇指与食指分开 | `NONE` | 稳定后结束上一个状态 |
| 手离开画面 | `NONE` | 立即复位，不等待稳定帧数 |

这一步只判断姿态。`PINCH` 不代表已经点击，`SCROLL` 不产生滚轮输出；阶段五在此基础上记录点击和拖拽事件。

### 状态机规则与参数

- 每次候选状态连续出现 `gesture_stable_frames = 3` 帧才确认切换；短暂变化不会切换，返回原姿态后重新计数。
- 捏合比例为拇指尖到食指尖的三维距离，除以手腕到中指根部的距离；计算前按实际画面宽高比修正坐标。
- 比例小于 `pinch_on_distance = 0.34` 进入捏合候选；捏合后只有大于 `pinch_off_distance = 0.42` 才释放，中间区间保留原判断。
- 食指按 `finger_min_angle = 155°` 判断。中指采用 `middle_finger_angle_hysteresis = 5°` 的角度迟滞：两个指关节均达到 160° 才可确认伸直，任一关节低于 150° 可确认弯曲；同时仍检查指尖到手腕的距离。状态变化还需连续 `middle_stable_frames = 2` 帧确认。临界区间保持上一次状态，单帧误判不会立刻将 `MOVE` 切换为 `SCROLL`。
- 状态切换先输出旧状态的 `*_END`，再输出新状态的 `*_START`；保持同一状态时不重复输出。
- 手丢失或关键点数值异常时立即回到 `NONE` 并清空候选、捏合及中指状态记忆。

参数位于 `aircontrol/config.py`。中指状态变化先经两帧确认，从确认那一帧起，手势整体仍需满足三帧稳定条件，因此从中指姿态开始改变到手势确认通常共需四帧（约 30 FPS 时为 0.1 秒）；滚动的启动和退出会比移动略慢；这有意优先减少误切换。捏合进入/退出阈值应保持进入阈值小于退出阈值。

## 阶段四预览

在项目目录运行：

```powershell
& E:\conda_envs\AirControl\python.exe -m aircontrol.stage4_cursor_preview
```

支持 `--camera 1` 和 `--model <路径>`，按 `Q` 或 `Esc` 退出。主屏幕尺寸通过 Windows API 读取，考虑 Windows 显示缩放；启动时不读取或改变真实鼠标位置。

画面中显示有效操作区域和右下角的屏幕示意图。黄色十字为未经平滑的目标，绿色圆点为平滑后的预计光标。暂停时示意图清空光标点，`Target` 和 `Mapped` 显示 `-`，不保留旧位置造成误读。示意图保持主屏幕的宽高比。

映射与恢复规则：

- 镜像画面中的食指位置直接映射，向右移动对应屏幕向右，向下移动对应屏幕向下。
- 默认操作区域为横纵坐标的 `0.15–0.85`，对应主屏幕 `0..宽度-1` 和 `0..高度-1`；超出区域时目标夹紧到屏幕边缘。
- 已确认状态和候选状态都为 `MOVE` 时才更新坐标；候选变为捏合、滚动或空闲时立即暂停，不等待确认状态切换。
- 使用按时间修正的指数平滑，当前 `smoothing = 0.25` 表示 30 FPS 下滤波状态单帧靠近目标的比例。越小越平滑、响应越慢；越大越灵敏。
- 再对滤波状态增加 `cursor_jitter_deadzone_px = 4` 像素的低速抖动过滤。实际输出相对滤波状态不足 4 像素时保持原位置；微小移动持续累积，达到阈值后更新，避免每帧的小位移被丢弃。阈值太大可能出现轻微粘滞或阶梯感。
- 速度上限为每秒 `1.5` 个屏幕对角线，单帧计算时间最多取 `0.05` 秒，限制异常位置和卡顿后的突跳；低于 20 FPS 时跟随会变慢。
- 首次进入已确认的 `MOVE` 时直接初始化到当前目标。候选状态离开 `MOVE`、手丢失或坐标无效时清空预计位置和滤波历史；重新确认 `MOVE` 后从当时的食指位置初始化，再正常平滑移动。

参数在 `aircontrol/config.py`：`cursor_margin_x`、`cursor_margin_y`、`smoothing`、`cursor_jitter_deadzone_px` 和 `cursor_max_speed`。阶段四不输出点击、拖拽或滚轮事件。

## 阶段五预览：左键点击与拖拽

在项目目录运行：

```powershell
& E:\conda_envs\AirControl\python.exe -m aircontrol.stage5_click_drag_preview
```

支持 `--camera 1` 和 `--model <路径>`，按 `Q` 或 `Esc` 退出。画面右侧继续显示阶段四的预计光标，状态面板会显示 `PINCHING`、`DRAGGING` 以及最近的模拟事件。控制台也会逐条输出事件。

本阶段只产生可观察的事件记录，不调用 PyAutoGUI、Windows 鼠标 API 或其他真实输入接口：

- `PINCH_START`：稳定捏合后进入模拟左键按下状态；点击位置固定为捏合前的预计光标位置。
- 快速松开且位移不超过 `drag_start_distance_px = 48` 像素时输出一次 `CLICK`，随后输出 `RELEASE_ALL`。
- 同一点击冷却时间 `click_cooldown = 0.35` 秒内再次快速捏合会输出 `CLICK_SUPPRESSED (COOLDOWN)`。
- 捏合移动达到 48 像素后输出 `DRAG_START`，之后仅在移动超过 `drag_move_epsilon_px = 1` 像素时输出 `DRAG_MOVE`；松开输出 `DRAG_END`，不会补发点击。
- 保持捏合但未进入拖拽，松开时已超过 `click_max_duration = 0.8` 秒则取消点击；候选变为 `NONE`/`SCROLL`、手部丢失、坐标无效或退出时，统一输出取消/结束事件和 `RELEASE_ALL`，清除模拟按下状态。

候选手势仍需连续 3 帧确认。启动时必须先进入稳定 `MOVE` 才会启用点击/拖拽；捏合或松开确认期间的坐标被冻结，避免手指姿态变化被误当成拖拽。重新开始操作前先回到稳定 `MOVE`，避免残留捏合立即触发新事件。

## 阶段六预览：页面滚动状态机

在项目目录运行：

```powershell
& E:\conda_envs\AirControl\python.exe -m aircontrol.stage6_scroll_preview
```

支持 `--camera 1`、`--model <路径>`，按 `Q` / `Esc` 或关闭窗口退出。保留阶段五的模拟移动、点击和拖拽，同时记录以下滚动事件：

| 事件 | 含义 |
|---|---|
| `SCROLL_START` | 确认食指、中指伸直，且未捏合；建立当前纵向基准，不立即滚动 |
| `SCROLL_UP amount` | 两指向上移动，产生正整数个向上滚动单位 |
| `SCROLL_DOWN amount` | 两指向下移动，产生正整数个向下滚动单位 |
| `SCROLL_END reason` | 候选离开滚动、丢手、关键点无效或退出；清空滚动基准 |

计算使用食指尖和中指尖的纵向中点，单位为摄像头画面像素，与屏幕分辨率和光标映射无关。只有确认状态与候选状态均为 `SCROLL` 时才更新；候选变为捏合、移动或空闲时停止，不等待整体手势确认。中指判断本身仍保留两帧确认。

滚动期间，右下角保留进入前的预计光标作为灰色静止点（若启动时直接进入滚动，没有旧光标则不显示点），`Mapped` 标记 `[FROZEN]`。这只是屏幕示意图，真实页面和鼠标均不会改变。点击和拖拽必须先从稳定 `MOVE` 启用；从滚动直接捏合不会触发按下，先回到 `MOVE` 才能点击。

参数位于 `aircontrol/config.py`：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `scroll_deadzone_px` | 18 | 相对上次输出/初始基准的纵向移动不足 18 个摄像头像素时不输出，小位移可累积 |
| `scroll_step_px` | 24 | 计算单位量的位移尺度 |
| `scroll_gain` | 4 | 单次输出量为 `max(1, int(abs(位移) × gain / step_px))`，随后受输出上限限制 |
| `scroll_max_steps_per_update` | 5 | 每次最多输出 5 个滚动单位 |
| `scroll_min_interval` | 0.1 秒 | 两次输出至少相隔 0.1 秒，即至多每秒 10 次事件、50 个单位 |
| `scroll_max_sample_gap` | 0.25 秒 | 相邻有效滚动采样间隔过长时，只重新建立基准，不补发滚动 |

每次输出后以当前位置重新建立基准，超出上限的位移直接丢弃，手停下后不会继续释放积压事件。死区默认值针对当前摄像头画面；更换分辨率、手部距离或光照后，手感可能需要调参。

## 阶段七：安全控制与真实鼠标接入

在项目目录启动预览（默认不发送系统鼠标输入）：

```powershell
& E:\conda_envs\AirControl\python.exe -m aircontrol.stage7_mouse_control
```

窗口获得焦点时按 `C` 显式启用真实鼠标，也可在启动时添加 `--control`：

```powershell
& E:\conda_envs\AirControl\python.exe -m aircontrol.stage7_mouse_control --control
```

`aircontrol/stage7_mouse_control.py` 是 A 方案备用入口，支持 `--camera 1`、`--model <路径>`。默认日常入口与 B 方案用法见阶段八。

| 按键 | 行为 |
|---|---|
| 窗口 `C` | 明确启用真实控制 |
| 窗口 `P` / 全局 `F8` | 暂停/恢复；首次纯预览时不会通过此键启用 |
| 窗口 `E` / 全局 `F9` | 锁定紧急停止，需退出重启后才能再次控制 |
| 全局 `Esc` | 停止控制、释放左键并请求退出 |
| 窗口 `Q` / 关闭预览窗口 | 退出并释放左键 |

启用、恢复和丢手后，先做出食指伸直、中指收起、拇指离开食指的 `MOVE`。画面从 `WAIT FOR MOVE` 进入 `CONTROL` 后才允许输入；已有捏合、直接滚动或手不在画面均不会解除这道确认。

真实输入与事件的对应关系：

- 稳定 `MOVE` 采用阶段四平滑坐标移动光标。主屏幕坐标限制在 `1..宽度-2` / `1..高度-2`，避免手势自动触发四角 Fail-Safe。
- `PINCH_START` 只保存锚点；`CLICK` 确认时才在该锚点按下并释放一次，冷却抑制和取消不会产生真实点击。
- `DRAG_START` 时在捏合锚点按下左键，此后用食指和拇指尖的中点跟踪拖动。检测到可能松开时先冻结坐标，持续至少 `drag_release_grace_seconds = 0.12` 秒后放开；期间重新捏合会接着拖。丢手、无效关键点和安全停止仍直接释放。
- 稳定 `SCROLL` 时使用 Windows `SendInput` 发送滚轮，按每格 120 单位换算，光标位置保持不变。先把光标移到要滚动的页面内容区，再伸直食指和中指并上下移动整只手；`SCROLL_START` 只建立起点。

终端中的 `SCROLL_UP/DOWN` 表示手势产生了滚动量；`output=WHEEL_SENT +5` 表示 Windows 接受了向上 5 格的输入。实际滚动哪个页面由 Windows 和应用决定。若显示 `BLOCKED_WAIT_FOR_MOVE`，先松开捏合、收起中指并稳定伸直食指，等界面进入 `CONTROL`。如果拖拽仍断开，查看 `DRAG_END` 后的原因或 `[CONTROL]` 状态变化，例如 `HAND_LOST` 或 `FRAME_TIMEOUT`。

暂停、紧急停止、摄像头中断、丢手、异常和退出都走释放路径。独立安全线程每约 20 毫秒检查全局 F8/F9/Esc，不要求预览窗口获得焦点；超过 `control_frame_timeout = 0.75` 秒没有完成一次帧更新时暂停并释放拖拽，恢复需重新确认 `MOVE`。保留 PyAutoGUI 的物理角落 Fail-Safe，触发后锁定停止；释放左键时仅临时绕过角落检查，随后恢复保护。

## 阶段八：B 方案日常使用与 A/B 对照

默认启动 B 方案纯预览。窗口打开后按 `C` 才启用真实控制；也可用 `--control` 直接启动控制模式（仍会先等待中立姿势）：

```powershell
& E:\conda_envs\AirControl\python.exe main.py
& E:\conda_envs\AirControl\python.exe main.py --control
```

支持 `--camera 1` 更换摄像头、`--model <路径>` 指定手部模型。默认预览不会发送系统鼠标输入。真实控制前，请先在空白窗口或可安全恢复的页面中试操作。

捏合并保持时光标以拇指尖相对移动；拇指与食指张开确认点击，光标会在候选离开捏合时冻结，并在原瞄准位置点击；张掌拖拽，食指与中指姿势滚动。

| 按键 | 行为 |
|---|---|
| 窗口 `C` | 启用或恢复真实控制，随后需连续 3 帧保持中立 |
| 窗口 `P` / 全局 `F8` | 暂停或恢复；恢复后重新确认中立 |
| 窗口 `E` / 全局 `F9` | 锁定急停，需退出重启后解除 |
| 全局 `Esc` | 急停并退出 |
| 窗口 `Q` / 关闭窗口 | 退出并清理 |

丢手、画面超时、暂停、急停和退出都会释放左键。

B 方案已取消超时后需要按键恢复的自动暂停。连续超过 `control_frame_timeout = 0.75` 秒没有完成帧更新时，只释放左键、清除旧手势和位移基准，并进入 `WAIT FOR NEUTRAL | FRAME_TIMEOUT`；摄像头恢复后，保持中立姿势连续 3 帧即可重新操作，无需按 `F8`。窗口 `P` / 全局 `F8` 的手动暂停和急停仍按上表恢复。

若虚拟光标仍移动、真实光标不响应，先查看 `Mode` 和 `Input`（虚拟预览在暂停时仍可移动）：

| 显示状态 | 原因与恢复方式 |
|---|---|
| `WAIT FOR NEUTRAL` / `HAND_LOST` | 曾短暂丢手；收起手指并分开拇指与食指，连续稳定 3 帧后再捏合 |
| `WAIT FOR NEUTRAL` / `FRAME_TIMEOUT` | 超过 0.75 秒没有完成帧更新；恢复画面后保持中立，无需按 `F8` |
| `PAUSED` / `PAUSED` | 手动暂停；按全局 `F8` 恢复，再保持中立 |
| `EMERGENCY STOP` | 急停或物理角落 Fail-Safe 已锁定；退出并重新启动 |
| `PREVIEW` | 尚未启用真实输入；在预览窗口按 `C` |
| `CONTROL` / `MOVE_SENT` | 程序已调用移动接口；若真实光标仍不动，记录此状态并继续排查系统输入层 |

终端输出 `[CONTROL]` 状态变化及恢复提示，手势事件同时带有 `mode` 和 `output`。手动恢复时会重新计时，避免用旧帧时间误判新一次超时。备用 A 方案的阶段七入口仍使用原来的超时暂停逻辑。

需要对照 A 与 B 时，另行运行：

运行单摄像头预览，在窗口按 A 或 B 切换方案；默认进入 A。此脚本默认只显示模拟事件和预计光标：

```powershell

```

可用 `--scheme B` 直接从 B 开始。切换方案会清理当前状态，不能把 A 中途的捏合/拖拽带入 B。

对照时 B 的真实控制启用和安全键与默认入口相同。进入控制后需连续三帧保持中立，界面显示 `CONTROL` 才开始操作。

| 方案 | 光标移动 | 点击 | 拖拽 |
|---|---|---|---|
| A（备用） | 食指伸直、中指收起时跟随食指 | 拇指与食指捏合后稳定松开 | 捏合期间移动越过阈值 |
| B（默认） | 拇指与食指捏合后，以拇指尖相对移动光标 | 保持其他手指收起，拇指与食指大幅张开并稳定确认 | 食指、中指与另外一指伸展，以拇指尖相对移动；姿势持续改变 5 帧后结束 |

B 的瞄准只用拇指与食指尖的归一化距离判断：进入比例 `0.42`、退出比例 `0.56`。稳定确认 3 帧后，捏合保持在迟滞区内即可移动，不再要求其他手指同时正确分类；相对移动控制点是拇指尖。点击仍要求拇指/食指大幅张开且其他手指收起，再稳定确认；有效捏合范围内持续移动，候选离开捏合时冻结虚拟光标；候选回到捏合时立即恢复并重建相对基准，避免补算冻结期间位移，确认点击时在已瞄准位置触发，不跟随张开过程中移动的拇指。张掌拖拽允许四指中一指漏判，拖拽专用伸指角度门槛约为 `140°`，拇指张开比例需大于 `0.65`；双指滚动与张掌姿势优先于距离分类。两者退出都需连续 5 帧确认，手部丢失仍立即结束。拖拽相对位移以拇指尖为基准。B 的相对光标从屏幕中心起步，灵敏度为 1.6；小幅目标差使用 `0.40` 平滑系数，目标差达到 80 屏幕像素时响应渐增至 `0.90`，降低快速移动时的滞后。这些参数为实验初值，需要根据摄像头实际识别调整。
